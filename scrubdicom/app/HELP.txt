SCRUB-DICOM: HOW TO USE THIS APP

What it does
  Takes a folder (or many folders) of cardiac CT exports and writes a separate, pseudonymised copy in which
  nothing in the header identifies the patient, the hospital or the scanner. The original scans are never
  touched. Every output file is checked before you share anything.

  This app never connects to the internet. It starts the same engine the command line uses, as a
  separate process, and shows you its output.

The four tabs are the four steps, in order: Anonymise, Check series, Verify output, Share safely.
The Dark / Light button in the header switches the look; it follows the system setting at first launch.

TAB 1  ANONYMISE
  Three cards: 1 Scans, 2 Output, 3 Options, then Preview / Anonymise. Hover a "?" for the details of any
  field. Rarely needed fields (drive path fix, already-analysed series, spreadsheet columns, scanner technical
  details, flat folders, automatic check) are behind the "Advanced" toggle at the right of the buttons.

  1 Scans: where they are, and what each patient will be called. Three ways:
    A list of patients (CSV)       Best for a cohort. A CSV with two columns: source_folder (the folder holding
                                   that patient's scans, anywhere on any drive) and study_id (the new ID).
                                   Can be stopped and resumed. Can keep only the coronary series.
    One patient                    One folder of scans, one new ID typed in.
    A folder of patients + an ID   One folder with a sub-folder per patient, plus a CSV or Excel sheet with an
    spreadsheet                    old-ID column and a new-ID column. Say whether the old ID is the Patient ID
                                   inside the scans or the sub-folder name. Column names are auto-detected;
                                   fill them in only if the detection gets it wrong.
    Already-analysed series        Optional CSV (study_id, series_uid, series_description) naming the series that
                                   has already been analysed and must be the one kept. A thick pick falls back
                                   to the thin coronary recon and the patient is flagged "needs a look".
    Drive path fix                 Only when the patient list was written on another computer, e.g. a Mac list
                                   run on Windows: /Volumes/Drive=E:\  rewrites every folder that starts with
                                   /Volumes/Drive.

  Step 2: where the anonymised copies go. Use a different drive from the scans, or at least a folder outside
  them. It will contain one folder per patient (named by new ID), plus _logs and _review.

  Step 3: options.
    Keep only the coronary CT angiogram series   drops scouts, calcium score, chest recons, lung/sharp kernels,
                                                 MPRs and dose reports. Every decision is shown on tab 2.
    Skip patients already done (resume)          leave on. Half-finished patients are redone.
    Keep scanner technical details               kernel and scan options. Leave OFF for a blinded read: a kernel
                                                 name identifies the scanner make.
    One folder per patient                       no per-series sub-folders.
    Check the output automatically when done     leave on.

  De-identification profile   what to keep beyond the default. "Blinded read" (the default) removes everything
                              identifying. Other profiles may keep sex, a 5-year age bucket, weight/height, dates
                              shifted by a secret per-patient offset, scanner make/model, technical fields, or the
                              institution name, and may set the patient name, study description and method text.
                              Private tags, UIDs, physicians, accession numbers, comments and addresses are always
                              removed. "Edit profiles..." copies a built-in and lets you tick what you need. The
                              profile is written into every file and into _logs/profile.json; Verify checks the
                              output against it.

  Buttons
    Preview        scans and reports what would be written; writes nothing. Do this first with a new list.
    Anonymise      shows the exact command, then runs it. The bar shows patient n of N and the time left; the
                   activity log updates live.
    Stop           ends the run cleanly. The patient in progress is redone next time.
    Open viewer    the built-in DICOM viewer (see below).
    More           show the command line (so a colleague can reproduce the run), open the output folder or the
                   log file, copy the log, show skipped patients in the log.
    Advanced       reveals the rarely needed fields and options.

THE VIEWER  (button "Preview a patient in the viewer..." on tab 1; "Open patient in viewer" on tab 2;
             "Review and redact quarantined files" on tab 4)
  Two views of the same window:
    Original scans     what Anonymise WILL do, computed in memory: every series with its keep/drop decision and a
                       thumbnail, the images, and the header before and after with each removed, changed or added
                       tag highlighted. Nothing is written. "Keep this series instead" records your choice next to
                       the patient list (series_picks.csv); the run reads it.
    Anonymised output  what WAS written, plus the quarantined files in _review. Draw boxes over burned-in text,
                       then "Apply and release": the boxes are painted black in the anonymised copy, the file moves
                       into the patient's folder, and the action is logged. Run the output check again afterwards.
  Viewing: mouse wheel or arrow keys scroll slices. The "Mouse drag" switch sets what a drag does: window/level,
  zoom, or pan. The Zoom slider, the + and - buttons, cmd/ctrl + wheel and 1:1 / Fit all zoom; double-click = fit;
  right-drag always pans; space = cine. kVp, mAs and CTDIvol are shown in the series list and bottom right. Presets for coronary, soft tissue,
  lung and bone windows. Axial, coronal and sagittal reformats (the series is loaded into memory once). The
  Hounsfield value under the cursor is shown top right. "Open this file in your DICOM viewer" hands the current
  file to a viewer application of your choice: "Open in viewer app" > "Choose viewer application..." once,
  then "This file" or "This series' folder" (Bee, Horos, Weasis, MicroDicom...).

TAB 2  CHECK SERIES
  One row per series per patient: kept, dropped, or "needs a look" (the engine used a fallback rule because
  the header lacked contrast or cardiac-phase information, or an already-analysed pick did not match). Look at
  those. Filter, search by new ID, export as CSV.

TAB 3  VERIFY OUTPUT
  Re-opens every output file and fails on any private tag, real date, original UID, vendor or institution
  text, person name, or any extra word you type: consultant surnames, the hospital's ODS code, anything
  specific to the cohort, separated by commas. The linking logs' original IDs are used automatically. The
  words you type are forgotten when you close the app. Do not share output that has not passed.

TAB 4  SHARE SAFELY
  The whole _logs folder is confidential, not just the LINKAGE file: the per-file and per-patient CSVs and
  the run logs record the original folder paths, and folders are usually named by hospital number.
  "Move the patient-linking logs out" moves everything except uid_salt.txt (needed so a re-run produces the
  same UIDs) and passed check reports to a folder you choose outside the output tree. Keep that folder with
  the linkage information, away from the scans. "Open quarantined files" shows _review: secondary captures,
  reports and PDFs whose headers are clean but whose pixels may carry burned-in text. Look before sharing.

ACTIONS MENU
  List patients whose kept slices are too thick      the slice rule is 0.8 mm (0.75 mm and thinner are kept).
  Remove those patients from the output so they      deletes their folders from the OUTPUT only; the next run
  are redone                                         with "Skip patients already done" redoes them. Asks first.

IF THE DRIVE DISCONNECTS
  The run stops by itself. Reconnect the drive, tick "Skip patients already done", click Anonymise.

IF NOTHING HAPPENS FOR MINUTES ON ONE FILE
  The log names the file. A failing drive is hanging on it. Stop, add the full path of that file to a
  skip_files.txt next to the patient list, and run again. That patient is then flagged "needs a look" because
  a slice is missing.
